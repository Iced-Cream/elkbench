# Template: an audio capture on an Analog Four MKII behind a level check, so a silent take stops
# the run instead of passing. The pattern's own trig plays T1 (grid recording: a key on the live
# screen adds no trig). The emulator's pass says nothing about sound: record the reference takes
# on the unit. Parameter reads (dump) of a voice go after the first hit: some values reach the
# voice only at note-on.
#
# The level check compares a short take with this plan's own reference take (level-ref.wav in its
# refs folder), recorded once on the unit from the same steps and kept. audio-compare fails on
# silence. No plan step writes into refs:
# the first unit run records the takes with audio-record alone (a copy of this plan without the
# audio-compare lines), and the person copies level.wav and take.wav from its run folder into
# this plan's refs folder as level-ref.wav and take-ref.wav. The channel numbers are
# Overbridge's for the A4 MKII: read them from a recording's .channels.txt before the go.
format = 1
name = capture with level check
unit = a4
refs = refs/a4-capture-with-level-check
out = runs
audio-tools = C:/path/to/elkbench/audio
audio-driver = Elektron Analog Four MKII  # the ASIO driver audio-record records from
audio-python = py -3.14               # a Python with numpy and scipy for the audio checks (testplan
#                                     # uses the daemon's own otherwise): set it to yours
note = ~T SETUP active, unsaved: T1 trig on step 1; stopped

[start]
wait 3
tap NO
wait 0.5
tap NO
wait 0.5
tap NO
wait 1.0
# The start check: the run's own test project is active (the setup plan ran first in this run).
# The home title row (rows 0-7) of a new project reads K001:KIT 1 and BPM:120.0. The contrast: a
# fresh card, and the built-in dirty and occupied starts, have another project or kit active, so this
# check stops the run there; this plan's
# own pass comes from run_plan after the setup plan.
say contrast fresh, dirty, occupied: another project or kit is active, so the title row differs
expect-screen test-project-title 2 rows=0-7

[setup: reload the test project from 121]
# The contrast: from the built-in testslot-cleared start, a new project is active but 121 is
# empty, so its panel has no LOAD FROM and the PROCEED check stops the run.
say contrast testslot-cleared: 121 is empty, so the reload finds no project to load
say proves setup: 121 is the active project and loads as a new one, so the pattern has no trig yet
# Earlier plans in the run may have toggled trigs in the working copy (grid recording toggles a
# trig: a second RECORD, 1, RECORD takes it away again). So the plan reloads 121 first, and 121
# must hold the setup's project with no trig: a plan that saves 121 reloads it before its change,
# or a trig saved there makes this plan's toggle remove it (the pattern then plays empty while the
# play indicator still shows playing, and an emulator gate can't hear that). A LEVEL
# turn makes the working copy unsaved, so the load always asks, and it asks only PROCEED WITH
# LOADING? because 121 is the active project (any other project asks SAVE ... BEFORE LOADING?
# first, and the check stops the run). 121 is reached in MANAGE PROJECTS (every slot, in order),
# not by its place in the LOAD PROJECT list, which follows what 122-128 hold.
tap T1
wait 0.5
tap OSC1
wait 0.6
turn LEVEL 8 4
wait 0.5
keys GLOBAL,UP,UP,UP,UP,UP,UP,UP,UP,UP,UP,UP,UP,YES,UP,UP,UP,DOWN,DOWN,YES
wait 0.8
keys FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),FUNC(DOWN),UP,UP,UP,UP,UP,UP,UP
wait 0.6
# 121's panel (RIGHT), LOAD FROM (fourth row from the top)
keys RIGHT,UP,UP,UP,UP,UP,UP,DOWN,DOWN,DOWN
wait 0.4
shot reload-121.png
tap YES
wait 0.8
expect-screen manage-proceed-with-loading 2 rows=21-43 cols=8-120
tap YES
wait 5
tap NO
wait 0.5
tap NO
wait 0.5
tap NO
wait 0.5
tap NO
wait 0.5
tap NO
wait 1.0
# a new project's home screen, compared whole
expect-screen new-home 3

[setup: oscillator retrig on]
say proves setup: both oscillators start each note in phase, so takes match below the note too
# Free-running oscillators start each note at another phase, and the bands far below the note
# then differ by several dB from take to take (seen on the unit with retrig off). TRG (knob G on
# OSC2's second page, OSC 1&2) restarts both in phase at each note. It belongs to the kit, so it
# is set after the reload. OSC2 steps between P 1/2 and P 2/2, so it is entered from FLTR: its
# first press opens P 1/2, the second P 2/2. An on/off value: one turn of 32 sets it, no YES.
tap T1
wait 0.5
tap FLTR
wait 0.6
tap OSC2
wait 0.6
tap OSC2
wait 0.6
turn G 32 8
wait 1.5
shot trg-on.png
# the page (OSC 1&2, by its knob labels and dials) with TRG on, compared whole below the title
expect-screen osc12-trg-on 2 rows=8-63

[setup: T1's OSC1 page, the sequencer stopped]
say proves setup: the page the trig is recorded from, and a stopped sequencer
# OSC1 steps between OSC1 (P 1/2) and NOISE (P 2/2), and a track key keeps the page, so OSC1 is
# entered from another page (FLTR): its first press then always opens P 1/2.
tap T1
wait 0.5
tap FLTR
wait 0.6
tap OSC1
wait 0.6
# then T1's OSC1 page 1/2, by its knob labels and dials (rows 8-63). The title
# bar names the page only for a moment before it goes back to the kit's name.
expect-screen t1-osc1-page 2 rows=8-63
# and the sequencer stopped (the stop square where the play indicator goes): PLAY on a playing
# pattern pauses it on the A4, and the setup's grid recording would run on a moving pattern
expect-screen stopped 2 rows=2-6 cols=119-125

[setup: one T1 trig on step 1, the pattern playing]
say proves setup: the sequencer starts T1 (a pattern trig, not a MIDI note)
tap RECORD
wait 0.6
tap 1
wait 0.3
tap RECORD
wait 0.6
tap PLAY
wait 1
# the play indicator only (a triangle playing, a square stopped): proves the precondition the take depends on
expect-screen playing 2 rows=2-6 cols=119-125

[level check (hardware)]
say proves works: T1 sounds at its reference level on its own channel (3) before any take
# Every take is a whole number of bars (a new project: 120 BPM, one T1 note per 2 s bar), so each
# holds the same notes wherever it starts. A 3 s take held one or two, and audio-compare's bands
# below the note then differed by several dB from the reference while the level matched.
audio-record 4 level
audio-compare level-ref level 3

[take (hardware)]
say proves works: the take, compared with its reference
# No audio-dropouts here: the new project's T1 is a raw saw, and a saw's reset once per cycle is
# a true discontinuity that its click test reports (audio/audiocheck.py). Judge clicks on a steady
# signal; on a synth track, audio-compare against the reference take is the check.
audio-record 10 take
audio-compare take-ref take 1,2

[after: the sequencer stopped]
say proves setup: the pattern is stopped again, so the next plan starts as the unit run does
# Not in a (hardware) section, so the emulator runs it too: an emulator reference recorded by the
# next plan then shows the sequencer stopped, as on the unit.
tap STOP
wait 1
expect-screen stopped 2 rows=2-6 cols=119-125
