# Template: a listening check on a Digitone. The listen text has three parts: what to hear,
# `allowed:` what the person may do on the unit by hand (or nothing), and `needs:` the audible
# precondition. The text is the instruction: a different instruction (said in the thread, say) is a
# different plan, with its own emulator pass.
#
# The Digitone screen shows nothing of PLAY (no page tried on OS 1.44 differs between playing and
# stopped), so the section proves on screen what the screen can show (track 1 TRIG page, entered
# from home), and a level check before it proves on the unit that track 1 sounds.
format = 1
name = listening check
unit = digitone
refs = refs/digitone-listen
out = runs
audio-tools = C:/path/to/elkbench/audio
audio-driver = Elektron Digitone        # the ASIO driver name, for audio-record on the unit
audio-python = py -3.14                  # a Python with numpy and scipy, for the audio checks
note = ~T SETUP (slot 121, CREATE NEW) active, T1 trig on step 1; stopped at the end
#
# The test project setup runs inside the plan (the same sections as setup-test-project.txt: CREATE
# NEW, SAVE PROJECT AS 121, LOAD FROM 121; its header says why not INIT NEW). With a digiemu that
# has setup snapshots, the emulator runs it once per build and resumes it after that
# (snapshot-after); the T1 sections stay after it, so every resumed run still checks keys and
# screens. Slot 121 is empty before the plan, as for setup-test-project (the last release's clear,
# or hand steps); the plan passes whether 121 was then still the active project or another project
# was. Every plan uses 121: each starts from empty test slots and its setup ends with 121 active,
# so no plan needs a slot of its own.
snapshot-after = setup: 121 is the active project

[start]
# Home first (NO closes SETTINGS and its panels), then MANAGE PROJECTS from the SETTINGS list's
# top (it does not wrap), then the cursor on 121 by a fixed count: FUNC(UP) and FUNC(DOWN) move
# eight slots, so 18 up reach the top whatever the remembered cursor, and 15 down put 121 in the
# list's bottom row.

wait 0.6

# The start check: 121's row (the list's bottom row, rows 56-63) shows an empty slot. The active
# project's row carries a small marker left of its name field (rows 58-60, cols 29-30), even when
# its slot has been cleared. digirun compares whole rows (it takes rows=, no cols=), so the check
# leaves the marker's rows out: rows 56-57 and 61-63 hold the slot number and the top and bottom
# rows of a name's letters, which an empty slot's dashed line does not light. Record it in the
# emulator, then see it fail with 121 filled.
expect-screen manage-121-empty 2 rows=56-57
expect-screen manage-121-empty 2 rows=61-63

# naming the working project. They are answered without a screen check: digirun compares whole
